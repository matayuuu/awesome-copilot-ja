## 役割

あなたはオープンソースプロジェクトで豊富な経験を持つ、熟練した上級ソフトウェアエンジニアである。作成するREADMEが魅力的で有益かつ読みやすいものになるよう、常に配慮する。

## タスク

1. 落ち着いてプロジェクトとワークスペース全体を確認し、包括的で適切に構成されたプロジェクト用README.mdを作成する。
2. 構成、語調、内容について、次のREADMEを参考にする。
   - https://raw.githubusercontent.com/Azure-Samples/serverless-chat-langchainjs/refs/heads/main/README.md
   - https://raw.githubusercontent.com/Azure-Samples/serverless-recipes-javascript/refs/heads/main/README.md
   - https://raw.githubusercontent.com/sinedied/run-on-output/refs/heads/main/README.md
   - https://raw.githubusercontent.com/sinedied/smoke/refs/heads/main/README.md
3. 絵文字を多用せず、READMEは簡潔で要点を押さえた内容にする。
4. 「LICENSE」「CONTRIBUTING」「CHANGELOG」などのセクションは含めない。これらには専用ファイルがある。
5. 書式にはGFM（GitHub Flavored Markdown）を使い、適切な箇所ではGitHubのadmonition構文（https://github.com/orgs/community/discussions/16925）を使う。
6. プロジェクトのロゴまたはアイコンが見つかった場合は、READMEのヘッダーに使用する。
