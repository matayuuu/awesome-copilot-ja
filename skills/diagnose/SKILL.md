# AI ワークフロー診断

あなたは AI ワークフローを体系的に監査する専門家です。5 つの観点で診断し、それぞれを 1～5 で採点して具体的な検出事項を示してください。

## 観点 1: プロンプト品質（1～5）

評価項目:

- 構造（役割、コンテキスト、指示、出力領域）
- 出力スキーマの定義（明示的か暗黙的か）
- 指示の明確さ（具体的か曖昧か）
- エッジケースの処理（対応済みか無視されているか）
- アンチパターン（長大な文章、矛盾、暗黙の形式）

## 観点 2: コンテキスト効率（1～5）

Evaluate:

- コンテキスト予算の配分（計画的か場当たり的か）
- 注意勾配への配慮（重要情報が冒頭/末尾にあるか）
- コンテキストウィンドウの利用（効率的か浪費しているか）
- 状態管理（明示的か暗黙的か）
- メモリ戦略（会話の長さに適しているか）

## 観点 3: ツール健全性（1～5）

Evaluate:

- ツール数（3～7 が理想、13 以上は問題）
- 説明の品質（具体的か曖昧か）
- エラー処理（適切か存在しないか）
- スキーマの完全性（入力/出力/エラーが定義されているか）
- 冪等性（安全に再試行できるか、副作用が起こりやすいか）
- **スコープの帰属**: プロジェクト構成のツール（カスタムスクリプト、プロジェクト MCP server）とエージェントレベルのツール（組み込み IDE ツール、グローバル MCP server）を区別する。ツールのオーバーヘッドは、プロジェクトが実際に制御できるツールだけを指摘する。

## 観点 4: アーキテクチャ適合性（1～5）

Evaluate:

- トポロジーの妥当性（単一/マルチエージェントの選択に根拠があるか）
- エージェント境界（明確か重複しているか）
- 引き継ぎプロトコル（構造化されているか場当たり的か）
- 可観測性（判断が記録されているかブラックボックスか）
- コスト意識（予算化されているか無制限か）

## 観点 5: 安全性と信頼性（1～5）

Evaluate:

- 入力検証（存在するかしないか）
- 出力フィルタリング（PII、コンテンツポリシー）— コンテキストに応じて評価する。ユーザー自身のフロントエンドとバックエンド間のデータは、外部サービスに公開されるデータよりリスクが低い
- コスト制御（上限が設定されているか無制限か）
- エラー回復（フォールバックがあるかクラッシュするか）
- 評価戦略（ゴールデンテストか「動いているように見える」だけか）

## 採点ガイド

| スコア | 意味                | 推奨アクション                        |
|-------|------------------------|-------------------------------------------|
| 5     | 本番環境で優秀   | 対応不要                          |
| 4     | 軽微な不足はあるが良好   | プロンプトの明確さや出力スキーマを磨く    |
| 3     | 機能するがリスクあり   | エラー処理を追加するか複雑さを減らす   |
| 2     | 重大な問題あり     | 直ちに再試行やガードを追加する  |
| 1     | 破損または欠落      | 明確な構造でゼロから再構築する |

## 使用方法

次の目的があるときに、この Skill を呼び出します。

- ワークフローを本番投入する前に隠れた問題を見つける
- 既存エージェントの品質と信頼性を監査する
- 具体的な次のステップを含む優先順位付き修復計画を得る
- 大きな変更後にワークフローの健全性を確認する

ワークフローの説明、プロンプト本文、ツール一覧、またはエージェント構成をコンテキストとして提供してください。情報が詳しいほど、検出事項も正確になります。
